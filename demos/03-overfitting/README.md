# Demo 3：亲眼观察过拟合

```bash
uv run demos/03-overfitting/main.py
```

CPU，无新依赖；80 个训练点，其中固定翻转 12 个标签，300 个干净验证点，1000 个独立测试点。标签翻转模拟标注错误。数据规则仍然是圆内 1、圆外 0。

## 看什么

打开 `outputs/flips-12/loss.png` 和 `boundaries.png`。训练曲线衡量对包含错误标签的训练数据的拟合，验证曲线衡量干净新数据表现，因此两条曲线之间的差距不能全部归因于过拟合；关键看同一模型随训练推进，训练损失下降而验证损失恶化的趋势。

基准结果：

| 网络隐藏宽度 | 参数数 | 早期最佳验证损失 | 2000 次更新后训练损失 | 最终验证损失 |
| --- | ---: | ---: | ---: | ---: |
| 4 | 37 | 0.3463 | 0.2143 | 0.5998 |
| 64 | 4417 | 0.3530 | 0.0003 | 1.2661 |

大网络几乎拟合了全部带错标的训练点，但验证表现恶化。边界图中的点按训练标签着色，黑圈标出被翻转的标签；灰虚线才是原本的圆。观察最后的边界是否为了错标点形成弯折或小区域。

## 早停如何工作

每 10 次更新检查验证损失。改善时用 `copy.deepcopy(model.state_dict())` 保存参数快照，避免继续训练修改同一份参数。连续 40 次检查没有改善时触发早停，即等待了 400 次更新。

为了展示后果，程序触发早停后仍继续训练到 2000 次，但冻结早停选定的检查点。图左列是保存的早期检查点，右列是继续训练后的模型。这是一个运行中展示两种选择，真实节省计算的早停会直接退出训练循环。

小网络在第 200 次更新保存最佳检查点，第 600 次触发；大网络在第 70 次保存，第 470 次触发。比较保存检查点的验证损失后，程序选择小网络，最后才生成测试集并评估一次，基准测试准确率 83.2%。未用测试结果决定宽度或停止位置。

## 从代码里读什么

1. `main()`：训练/验证数据、只翻转训练标签、候选模型选择、最后测试。
2. `train()`：熟悉的训练循环加上验证和保存状态。两个网络都有两层隐藏层，只有宽度不同。优化器换为 Adam，它基于梯度并自适应缩放更新；两个实验使用相同设置，此处先不展开 Adam 公式。
3. `evaluate()`：no_grad 下计算损失与准确率，不更新参数。

## 动手对照：移除错标

```bash
uv run demos/03-overfitting/main.py --flip-count 0
```

结果保存到 `outputs/flips-0/`，不会覆盖基准图。种子、输入点、模型初始化和其他设置均相同，只改变错标数量。比较验证曲线与边界，先预测再看结果。测试集会在每次运行末尾评估；继续探索时按训练/验证曲线讨论，若根据这些测试结果反复调参，就需要新的最终保留测试集。

更大网络不是必然更差，早停也不保证解决全部错误。结论限定于当前小数据与标注噪声实验，不据此给所有任务选择模型规模。
